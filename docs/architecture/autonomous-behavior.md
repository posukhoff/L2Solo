# Автономное поведение

**Статус:** описание [ADR-002 — Accepted](../adr/002-decision-system.md). Требования к результату: [REQUIREMENTS.md](../REQUIREMENTS.md).

## 1. Выбор Goal

Account, CP, Clan и Alliance выбирают конкретные результаты исходя из собственных интересов, потребностей и обстоятельств. Party может определять результаты в пределах совместной деятельности.

Игровые правила и доступные знания помогают узнать, что вообще возможно: требования профессий, уровней, рецептов, способы получения предметов, условия осад. **Игровым областям не нужен собственный AI-генератор Goal.**

- У Goal один владелец и проверяемое условие достижения по авторитетному состоянию мира или истории игровых событий.
- Несколько Goal могут быть активны одновременно; одно занятие может помогать нескольким.
- **Для выбора Goal не требуется полный план**, точная оценка затрат, времени, вероятности успеха или заранее определённый способ достижения. Грубая оценка доступности — возможный ориентир, не обязательная процедура.
- Фарм, поиск рецепта и доставка ресурсов не становятся подцелями автоматически. Обязательного дерева Goal нет.
- Goal не нужно создавать для каждого игрового действия. Выполненные и потерявшие смысл Goal пересматриваются при значимых изменениях; невозможность текущего занятия сама по себе не отменяет Goal.

## 2. Выбор Activity

У Account есть **один общий набор актуальных вариантов**: личные занятия, включая занятия ради Goal, и обязательства перед другими участниками. Отдельных планировщиков для Account → CP → Clan не требуется.

| Параметр | Значение |
| --- | --- |
| **Занятие** | Конкретная текущая деятельность: фарм, торговля, рейд, осада |
| **Числовой приоритет** | Исходная важность плюс небольшие ситуационные модификаторы |
| **Актуальность** | Когда можно/нужно начать, включая подготовку и время дороги |
| **Охват** | Какие Account или группы должны участвовать |

Числа и формулы **пока не фиксированы**. Срочность, изменение обстановки и личная заинтересованность могут менять оценку. Источник решения — Clan или CP — не добавляет автоматически высший приоритет.

Выбирается самое приоритетное **применимое и допустимое** занятие. Если текущее невозможно, выбирается другое без автоматической отмены Goal. При близких значениях обычно продолжается текущее. Пересмотр — при завершении занятия, значимом изменении условий, новом актуальном обязательстве или наступлении времени подготовки к нему; не на каждом игровом тике.

## 3. Obligation, Request и команды

| Понятие | Поведение |
| --- | --- |
| **Obligation** | Обязательная для затронутых участников деятельность из решения CP/Clan/Alliance в пределах полномочий либо из принятой договорённости |
| **Request** | Просьба или предложение о помощи, торговле, сотрудничестве; до согласия или допустимого решения не обязывает |
| **Команда** | Немедленное действие в текущем игровом контексте («атакуй», «бафни», «отступаем»), исполняется локально |

Одно Obligation может охватывать один Account, несколько CP или доступный Clan **без записи-копии для каждого участника**. Его приоритет, условия и участники могут меняться; расширить обязанности других нельзя одной только сменой числа приоритета.

CP может попросить Clan о подкреплении, но просьба сама по себе не передаёт Goal и не назначает других участников. Когда Clan решает привлечь силы, обязанность касается только выбранных участников.

Обязательство завершается после выполнения, допустимой отмены или утраты актуальности согласно его условиям. После этого оно не участвует в выборе Activity.

Request не обязательно должен быть постоянно хранимой записью: иногда это обычное сообщение.

## 4. Переключение и исполнение

Если новое обязательство или занятие стало существеннее, Account безопасно прерывает текущее исполнение. Его Goal и действующие Obligation сохраняются, **подробный план прерванного занятия сохранять не нужно**. Затем Account снова выбирает из доступных занятий.

Внутри деятельности локальные игровые правила управляют атакой, лечением, отступлением, движением и сделками. Немедленная реакция на опасность не равна новой стратегической Goal.

Доступные способы исполнения зависят от хроники. Для получения предмета могут подходить дроп, спойл, крафт, NPC-магазин, частная торговля или помощь; не нужно заранее разворачивать все альтернативы в дерево.

## 5. Организации, права и информация

Решение CP/Clan/Alliance принадлежит объединению; лидер может сообщать его реальным игрокам, но не владеет отдельным AI. Команды уполномоченного человека имеют преимущество перед автономным выбором в пределах его прав и не позволяют управлять чужим реальным Character. Это не дополнительный числовой модификатор Activity.

Игрокам доступны справочные знания хроники; текущее состояние рынка, местонахождение соперников и занятость спота узнаются через разрешённые игровые способы. Объявления и Request не требуют постоянного анализа каждого чата всеми Account.

**Не определено здесь:** алгоритм сравнения Goal, коэффициенты приоритетов, хранение Obligation, протокол общения, детали боя, экономика и технология исполнения на 7 000 Account. Эти вопросы фиксируются в [BACKLOG.md](../BACKLOG.md), без обязательного Planner или отдельных AI для каждой роли.
