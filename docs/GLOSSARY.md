# Глоссарий L2Solo

> **Для новой версии L2Solo.** Код и архитектура прежнего эмулятора — только справочный материал. Термины ниже описывают целевую систему, а не существующие классы.

Глоссарий — общая точка входа для терминов. Здесь даются короткие объяснения; подробные правила находятся в [доменной модели](architecture/domain-model.md) и [автономном поведении](architecture/autonomous-behavior.md). **Утверждённые инварианты** закреплены в [ADR-001](adr/001-domain-model.md); модель поведения пока обсуждается в [ADR-002 (Draft)](adr/002-decision-system.md). Включение термина в словарь не означает, что мы обязаны создать одноимённый класс, сервис или таблицу.

## Игроки и объединения

| Термин | Простое объяснение |
| --- | --- |
| **Account (аккаунт)** | Самостоятельный реальный или виртуальный игрок. Имеет собственную идентичность, персонажей, интересы и социальные связи. |
| **Character (персонаж)** | Игровое воплощение аккаунта: уровень, профессия, позиция, инвентарь, действия. Один Character всегда принадлежит одному Account. |
| **Main Character** | Текущий основной персонаж Account; может меняться и не обязательно является персонажем, которым сейчас управляют. |
| **NPC** | Мирный NPC, монстр, босс, торговец, страж и т. п. Имеет игровые правила и реактивное поведение, но не личность уровня Account. |
| **Party (пати)** | Временная группа **персонажей** для совместных действий, в том числе из разных CP или кланов. |
| **CP (конст-пати)** | Устойчивое объединение **аккаунтов**, действующих совместно и способных иметь общие цели и ресурсы. |
| **Clan (клан)** | Организация, объединяющая CP и/или отдельных Account, со своими целями и руководством. |
| **Alliance (альянс)** | Объединение кланов; социальный союз может отличаться от официального альянса конкретной хроники. |
| **Субъект (Subject)** | Общее слово для Account, Party, CP, Clan и Alliance, когда речь о возможности принимать решения. **Не отдельная сущность** и не утверждение, что это пять одинаковых AI. |

## Принадлежность, контроль и ресурсы

| Термин | Простое объяснение |
| --- | --- |
| **Социальная принадлежность** | К какой CP или Clan Account относится как участник сообщества. Не даёт автоматически формальных игровых прав. |
| **Формальное членство** | Официальное участие Character/Account в механиках клана и альянса по правилам конкретной хроники. Отличается от социальной принадлежности. |
| **Полномочие (Authority)** | Право субъекта или лидера отдавать обязательное распоряжение либо совершать определённое действие. Не равно способности технически исполнить команду. |
| **Контроль Character** | Источник непосредственных команд персонажу: человек или автономное поведение. Конфликтующие контроллеры одного Character недопустимы. |
| **Владение ресурсом** | У предмета и адены одно авторитетное место хранения; интерес организации к предмету не означает его копирования или автоматической передачи. |
| **Игровое состояние** | Реальные данные мира: персонажи, позиции, HP, прогресс, предметы, сделки, членство и другие факты. Правила их изменения принадлежат игровым подсистемам. |

## Цели и деятельность — рабочие определения ADR-002

| Термин | Простое объяснение |
| --- | --- |
| **Goal (цель)** | Конкретный желаемый результат с владельцем и проверяемым условием достижения. Не содержит обязательного способа его получения. |
| **Кандидат на Goal** | Возможный результат, предложенный игровой областью для рассмотрения. Не становится целью автоматически. |
| **Условие достижения** | Как по авторитетным игровым фактам определить, что конкретная Goal выполнена. |
| **Связанная цель / подцель** | Самостоятельный результат, который может помогать другой цели. Обязательное дерево целей и автоматическая зависимость статусов **не утверждены**. |
| **Activity (деятельность)** | То, чем персонаж или группа сейчас занимается: фарм, торговля, путь на сбор, осада, поиск пати. Не каждое занятие требует Goal. |
| **Приоритет деятельности** | Правило выбора между актуальными занятиями и обязательствами. Это не приказ немедленно отменить игровое действие. |
| **Обязательство (Obligation)** | Договорённость или действующее распоряжение, которое нужно учитывать. Может возникнуть между двумя Account, в Party или в рамках CP/Clan. |
| **Assignment (поручение)** | Конкретная работа, порученная исполнителю, если её нужно отдельно учитывать. Не обязательна для каждой договорённости или команды. |
| **Request (запрос)** | Просьба, предложение или объявление о потребности. Сам по себе не передаёт Goal и не создаёт обязательств у получателей. |
| **Охват участия** | Кого касается конкретная коллективная деятельность: отдельных участников, CP, нескольких CP либо всех доступных членов организации. |

## Общение и исполнение — темы будущих решений

| Термин | Простое объяснение |
| --- | --- |
| **Доска общения (Board)** | Предлагаемая среда для сообщений, WTB/WTS, поиска Party, просьб о помощи и других объявлений с доступом по локальному, клановому, CP- или иному контексту. **Проектное направление, не утверждённая реализация.** |
| **Игровая область** | Часть правил и поведения мира: развитие, экипировка, экономика, крафт, бой, перемещение и т. д. Название зоны ответственности, не обязательный отдельный сервис. |
| **Локальное поведение** | Реакция во время текущей деятельности: кайт, атака, смена маршрута, побег, выбор цели боя. Не требует пересмотра долгосрочных Goal после каждого изменения. |
| **Hot / Cold** | Условные названия подробного и облегчённого способов симуляции. Конкретная модель **ещё не утверждена**; Cold не означает офлайн или остановку жизни персонажа. |

## Как читать архитектурные документы

- **[ARCHITECTURE.md](ARCHITECTURE.md)** — карта новой архитектуры и статусы решений.
- **[Доменная модель](architecture/domain-model.md)** — что существует, кому принадлежит, кто вправе действовать.
- **[Автономное поведение и координация](architecture/autonomous-behavior.md)** — как выбирают цели, занятия и сотрудничают; **рабочая архитектура, ещё не Accepted**.
- **[ADR](adr/)** — какие решения приняты, почему и с каким статусом.
- **[Заметки](notes/)** — ещё не утверждённые сценарии и вопросы.

Если определение в этом файле расходится с принятым ADR, действует принятый ADR; расхождение нужно исправить в документации.
