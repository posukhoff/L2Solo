# Economy & Inventory — заметки к будущему ADR

- **Статус:** рабочие договорённости и отложенные вопросы; **не** спецификация реализации.
- **Источник:** обсуждение ADR-002; принятая граница владения — [ADR-001](../adr/001-domain-model.md).

## Сохранить

- Character хранит личный инвентарь, Account — общий склад персонажей, **CP владеет собственным CP Warehouse**, Clan — Clan Warehouse. CP Warehouse уже закреплён в Accepted ADR-001; это **не** скрытый альт-кладовщик.
- Goal **не** хранит физические предметы. Для цели может быть логически выделено или зарезервировано некоторое количество ресурсов; авторитетное хранение, проверка доступности и атомарное перемещение — зона Inventory/Economy. Один предмет/количество адены не должны учитываться как одновременно доступные для двух конфликтующих операций.
- Поиск и приобретение товаров — разные реальные игровые пути:
  - **Чат:** узнать предложение → договориться о цене и встрече → добраться → провести допустимый обмен.
  - **Private store:** прийти в торговую область → осмотреть доступные лавки → найти предложение → купить по выставленной цене.
  Переговоры не нужны для каждого магазина; наличие предложения нельзя получать из глобальной всеведущей таблицы.
- Бот-бот: не требуется имитировать UI торгового окна или клики. Человек-бот: соблюдается игровой протокол и подтверждения клиента; **одни и те же проверки и экономические инварианты** для обоих. Физическая достижимость и ограничения по хронике не обходятся оптимизацией.
- Ограниченный диапазон цены/условия могут позволить экономическому поведению вести повторные предложения без стратегического пересмотра каждого шага; решение о новом бюджете — за владельцем цели.
- Офлайн-лавка — пассивное предложение Character; постоянный активный AI ради её существования не нужен.

## Открыто для Economy ADR

Права и логистика CP Warehouse, способы доступа, резервирование, конкурирующие покупки, момент фиксации сделки, согласование и отмена, ценовые политики, информация о рынке, поведение спроса/предложения. **Не** удерживать блокировку БД на всю дорогу к встрече; конкретный механизм транзакций выбрать отдельно.
