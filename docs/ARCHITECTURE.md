# L2 Solo — архитектурная карта следующей версии

> **Важно:** текущая ветка `main` репозитория содержит существующий C4-эмулятор. Документы в `docs/` фиксируют **планируемую архитектуру следующей версии**, а не утверждают, что текущий код уже ей соответствует. Проектирование и реализация ведутся последовательно; одно утверждённое ADR не означает готовность следующей подсистемы.

## Основные принципы

- Account — единая идентичность реального или автономного игрока; Character — его игровые персонажи.
- Party объединяет Character, CP — Account; Clan объединяет CP и одиночных Account, Alliance — Clan.
- Социальная принадлежность и формальное игровое членство различаются.
- Цели, полномочия, источники решений (Manual / Rules / опционально LLM) и игровые исполнители независимы.
- Не создавать тяжёлую самостоятельную сущность для каждого боя, NPC, спота или вида стратегии организации.
- Контракты и инварианты должны оставаться устойчивыми к смене TS/Node-реализации, оптимизаций или будущему переносу отдельных частей в Rust.
- Производительность на целевых 10K персонажей **ещё не доказана**; нужна отдельная архитектура исполнения и бенчмарки.

## Рабочий порядок

1. Выбрать один архитектурный вопрос из backlog.
2. Обсудить варианты и компромиссы **по одному**, не перескакивая к соседним подсистемам.
3. Зафиксировать минимальное решение в отдельном ADR с инвариантами и границами.
4. Получить утверждение; только после этого считать решение Accepted.
5. Реализовать и проверить поведение/производительность, затем уточнять решения по фактам, а не ради гипотетических расширений.
