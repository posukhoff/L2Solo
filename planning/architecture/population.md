## Lifecycle

1. Seed → `LifeState.upsertState` writes cold rows. Merchants are the only static bots.
2. Start: `LifeState.init` (NodeL2 `startServer`, before `AfkTrade.init`: the board migrations and the meeting marker rewrite and recovery write life rows into its cache; a stale hot copy there failed the init's repair saves), `BackgroundPartyState.init`, worker; pages `init` → `catalog_page` → `table_page` → `snapshot_page`; geodata shared through `workerData`.
3. Worker step: `lifecycleKind` → `resolver` | `command` | `party` | `party_member` | `event_driven` | `inactive`. Resolver: `planLifecycle` → `resolveSolo` (a hunting step always runs on round by round in `huntWindow`, each round projected by `prepareResolve`, until `ColdSoloWindow.endOf`, 32 rounds or a stalled clock (limits.md "Solo hunt window"); a kernel built without the worker's window readers, in tests of other rules, runs one round a step) → `projectResolve` → `prepareResolve` → `proposal_batch`.
4. Main commit (the worker sends a finished half window at once, any step after its batching age; main commits half a window per turn, a party whole; limits.md "Steps in flight", "Full-window commit"): `handleProposalBatch` → `ColdCommitQueue` → `Owner.commitBatch` (DB CAS) → `afterCommit` (caches, economy decision, board, equipment, clan events, party; each a named `step`) → `commit_ack`; the bot's plan, buff and training run in the review command the worker sends on that ack.
5. Command: worker `command_request` with `precomputedResult` → `executeWorkerLifecycleCommand` → `resolveColdState` (shopping, crafting, market, halls, `NeedsEvaluator.goal`) → `command_ack`.
6. Cold → hot: `activateNearPlayers` (or invite, remote chat) → `fenceBot` (advisory) → `handoffToMain` (**the real guard**, DB revision CAS) → `loadAndSpawnBot({coldLifeState, …})` → `markHot`. A party / PvP group goes through its own `transition` (`Database.transitionBackgroundParty` / `transitionPvpEncounter`), POP-4. The perf tool's players (`HotCrowd`, [e2e.md](e2e.md)) heat crowds by this same path. Vitals: solo near (`readyOnActivation`) fills HP/MP, stands a dead row up; party fills; PvP keeps the row's (threads-1).
7. Hot → cold: `cooldownEligibleHot` → `Cooldown.cooldown` (`canCooldown`) → `markCold`/`writeColdRow` → `transitionToColdState`: `upsertState({phase:'cold'})` → `acceptColdState`; worker refusal marks the bot hot again.

## Situations (how every bot decision wakes)
- Rule: a bot decides like a C4 player, rarely, at named situations, and holds the answer until the next one. One mechanism, `Situations.js`: the catalogue (owner, payload, where heard) and `DECISIONS` (each declares once which situations wake it). Owners raise; decisions only declare. Bits written only by `Situations.raise` (both threads), cleared only by `Situations.decided` (the decision that took them); no input versions, intervals, replays or per-decision wake logic.
- Read when deciding, never a wake: prices and board quotes, crowd at other spots, money drift and weight, own samples, the spot catalogue, relations, bag counts above the line, own outputs (`arrived_spot` on its own trip, the search's answer, `own_move`, own warehouse deposits, the money weight, a party request, own lines and purchases), field loot, a level alone. No clock for waking except known ends (deadlines set once when a wait starts, each a limits.md row); a situation with no event yet is a problems.md line, not a timer.
- Store (layout owner `Situations`; mind keys `SavedStats.MIND_KEYS`): `stats.woken` a bit per decision; `stats.waiting` the same bits on a STOP plane (low byte) and a TOWN plane (next byte), 8 decisions fit (limits.md "Decision bits"); `stats.situationSeq` counts raises that added a bit (a hold key only); `decisionSeq` moves on `decided(build)`, WishNetwork's focus bump and `Agenda.moved` (card echo and roll seed). No `woken` on a row = all woken once (`EconomyRestartDecision.VERSION`); no held answer = woken (`HELD`: earning_spot → `stats.earning`, build → `stats.wishSections`). Held in the mind: `stats.earning {spotId|null, shots, income, expected, earning, error, at, shotKind, shotsPerHour, potionsPerHour, drinks}` (`EquipmentIncomeRoute.answerOf`, re-evaluated at current prices by `heldRoute`), `stats.spotMarks [{spotId, reason}]` (reason = the marking situation; forgotten at the situations its owner declares, `Situations.forgets` ← `SpotRiskPolicy.LIFETIME`: the outing's end, arrived_town(:own)/died/gear_changed/grade_changed, spot_dangerous also party_left), `stats.gearMarks [{key}]` (failed gear errands, forgotten at `GearMarks.LIFETIME`, which wakes gear_plan), `stats.huntSpot {spotId}` (the route's one choice, published by the worker), `stats.stay {spotId, kills, net, ms, judged}`, `stats.affordAt {at, kind}`, `stats.rebuff {via, providerId}`, party `partySpot`.
- Main's raise on a far bot (`raiseDecision` on a cold row, a rejected command `DecisionEvents.rejectOnRow`): `BotLifeState.raiseOnRow` ([persistence.md](persistence.md); ORs woken/waiting by `json_set`, `situationSeq + 1`, `simulationRevision + 1` `WHERE phase='cold'`; an in-flight worker commit is refused and rebases); a row found hot → the body's bag; landing nowhere is counted (`situations.raise_lost`); main's counts join the worker's on the line. Party rows: the worker's party step diffs the party's facts.
- Places: `OPEN` (near body off the field, a far bot's town-arrival step), `WORK` (hunt, road, party fight), `REST`, `VISIT`, `STAND` (stall, craft, meeting), `BODY` (near body in the field). Heard where the bot stands wakes its decisions, else they wait on its plane: WORK/BODY hear NOW only, REST hears STOP, town/stall/meeting hear STOP and TOWN. Stops (`Situations.stop`, every far step in `prepareResolve`): every solo window end, a hot body's rest end (`RestingState` → `DecisionEvents.stop`, ≈3/h per hot bot, one near decision each) and town arrival (`arrived_town`, both planes), a party's round end. The hunt window ends on a woken decision (`ColdSoloWindow.endOf`), not on what waits; a new grade waits for the rest. Player-facing situations are immediate (invite, trade request, buying from the bot's store, attack, command, a party with a player).
- Deciding (worker only; main reads the card, never rebuilds it): none woken → serve the held card (counted, clears no bit); woken → take those only, each calling `decided` (the build's publish, `EconomyContext` statsPacket), in the order earning_spot → workshop → build → own_lines; the step packet carries only what its decisions changed (`Situations.stepMind`), landed over the round's row by `landMind` in `prepareResolve`, so a raise after the decision (the trip's ask, a lost arrival contest) survives; the earning spot's bit is cleared only by its search, inside a build or alone (`EconomyContext.earningDue`, `decideEarning`). The worker's accepted decision wakes a body (`BotAI.wakeup` on `economy_decided`). A body whose answer names no spot it may take asks once per answer (`Situations.spotAsk` → `spot_empty`; none again: `earning:no_spot`, the defined fallback).
- DECISIONS (code `Situations.DECISIONS`, 7 bits; a visit's stops ride the build's agenda, no town-plan bit): earning_spot (grade_changed, spot_outleveled, gear_changed, died, recovered, spot_disappoints, contest_lost, spot_empty, spot_dangerous, spot_unreachable, moved_by_world, party_left, shots_out, goal_affordable:potions, karma_changed; player_command writes the answer, wakes nothing); build (arrived_town, grade_changed, gear_changed, recipe_learned, party_left, goal_affordable:potions/focus, out_of_money, goal_done:goal, goal_failed, goal_done:visit, goal_failed:visit, stock_low:shots/potions, bag_full, source_stalled, clan_call, clan_changed, spot_empty, player_command, spot_unreachable, offer_posted — an offer alone writes `stats.offerWake` {itemId, seq} (`Situations.offerWoke`, valid while the build bit and seq hold): the held step can lose only to a buy of that item, focus kept; any other build raise clears it); gear_plan (grade_changed, gear_changed, clan_changed, source_stalled); workshop (arrived_town(:own), recipe_learned); own_lines (arrived_town(:own), line_undercut, goal_done:line, goal_failed:line); rebuff (buffs_expired, arrived_town(:own)); party_stay, a member's (died, bag_full, goal_affordable:focus, grade_changed, party_outleveled, party_need_ended). `PARTY_DECISIONS`: party_spot (member_joined, member_left, contest_lost, spot_dangerous, spot_empty, spot_outleveled; no answer = woken). Spot subject (traced, no bot): spot_contested, enemy_met.
- Near body: main detects its own facts on each post (`BotLifeState.notifyNearFacts` → `DecisionEvents.detectNear`: `Situations.detect` of the posted row against its decision's baseline, the last one received; a fact the baseline lacks against its previous post, kept as its fact digests and money mark only in `session.nearFacts`, dropped at cooling) and names them in its bag (`session.nearRaise = {seq, names: [{name, payload|null, seq}, …] ≤ 16, impossible, impossibleSeq, impossibleName, stop: rest|town, named}`, a new seq only when an entry joins (an entry: the name and its payload's spot, or kind and key); a named raise or a stop flushes the post at once; an answer prunes the entries it applied); the worker raises the bag where the body stands (`Situations.bodyPlace`: in the field its decisions as at work). A body's moves are its own (`detect`'s `body`: no `moved_by_world` from its occupation): its spot change is a post of its own (`SpotService.assignSpot` → `near_spot`, `leaveSpot` → `near_left` with spotId null, both sent at once), heard on the worker by the spot aggregate's hot arrival hook (`ColdSimulationWorker.nearArrival`, by the post's numbered `nearSpot`, counted `spot:arrival@hot` / `spot:left@hot`). Main's copy of a body's stats is replaced, never edited in place (`DecisionEvents.replaceStats`: raise facts, an answer, groundLook's `emptyGround`).
- Money wakes only at its thresholds (`DecisionSections.moneyCrossings`: the wallet now against the build's armed `affordAt` (`affordAtOf`: potions, the weapon bridge, else the nearer of the focus and the gear plan's market piece) → `goal_affordable:<kind>` and its held leaf's funded row `fundedAt` → `out_of_money`, raised while the wallet stands past them: a raise on the woken build is no news; the build re-arms them, the agenda's move drops the passed ones, `DecisionSections.unspent`), in the step's diff and a body's posts alike, so money main adds between steps is heard at the next one.
- Raisers: `detect` over own state (`factNames`: grade_changed via `GearGradeRule.gradeForLevel`, spot_outleveled past `ProgressionRates.DEEP_BLUE_LEVEL_GAP` (heard at once — a far bot at its next step — once per spot outgrown, wakes earning_spot only; spot_disappoints still waits for a rest), gear_changed = `ColdCombatProfile.gearOf` (weapon, body armour grade, whole sets; heard in town only), clan_changed, recovered, died, moved_by_world, karma_changed, party_left at `releaseMember`, shots_out/stock_low at the one-hour line (`lineOf`), bag_full = `PartyMarketBreak.bagFact`, goal_affordable/out_of_money at `stats.affordAt`/the leaf's funded row, source_stalled at `equipmentPlan.stall`); `BotHuntEfficiency.disappoints` (spot_disappoints at a rest after 50 kills: net/h < expected × (1 − 2/√kills), cold solo only); `SpotContest` at an arrival (contest_lost/spot_empty), resolver `unhuntable`, hot `groundLook`; executors where they act (goal_done/goal_failed, 5 faults, main's refusals; goal_done:line also a sale or a service fill); hot `ShoppingState`/cold `detect` (arrived_town, `:own` the leaf's trip); board line events (offer_posted, line_undercut); `buffed` 1→0 and hot `EffectTicker` expiry (buffs_expired); the stores fact (clan_call, until the clan planners raise); `CraftWorkshopService.recipeLearned`; `CharacterVisibility.afterSend` (player↔bot enemy_met).
- Not situations: training (the level-up fact's consumer in the round; the class record's one writer is main's training, `BotClassProgression.reconcile` from `characters.classId`, `durable.classId` its trigger), party_request (the build's output), activated, spot_crowded (→ contest_lost), invited (`BotAvailability` reads the held plan), money drift, own_loss, crafter_mp, threat mask, quantity bands.
- Aggregates: spot (worker: row "Spot aggregate at arrival"; main posts hot `near_spot` (only when a walk or trip ends, not at a cell border)/`near_left`, its index a mirror); party (`party_spot` on the worker; forming on main judges only seekers: an open request or a clan call; a refused roster held on its group's revision); clan (help on members' moves `ClanPartyHelp.observe`, duty hold without due, board wakes only level 2 clans on their proof's offers, war review only where C4 allows war); board (main the only publisher; `MarketBuyerWaiters` holds buyers' wants registered at `decided(build)` (limits.md "Board buyer wants"); the worker's board diff raises line_undercut and goal_done:line). Threads: decisions on the worker for hot and cold units; main posts, executes answers, keeps tactics; player↔bot enemy_met decided on main.
- Decision trace at `raise` and `decided`: level 1 counters always on (`situations=raised:<name@place>…;woke:…;decided:<decision>:<taken>/<served>`, per bot-hour in `perf.js report`; also `situations.search`, `unwoken`, `party_solo:none`, `earning:no_spot`, `spot:contest:*`, `enemy_met:*`, `kit:basics`, `board:wait:capped`, `step:wake:lost`); level 2 off by default (`[BotPopulation] decisionTrace`: situation@place → decision → answer, executors, deaths with the killer, worker restarts, FailureLog sites; via the history worker, kept 48 h, rate-bounded with a counted drop; `scripts/trace.js`). Status line, diagnostics off too: `situations=raised:<name@place>:<n>,…; woke:<decision><name|stop@place>:<n>,…;decided:<decision>:<taken>/<served>,<decision>:unwoken:<caller>:<n>,…` (`Situations.counts`, the worker's heartbeat `situations`); unwoken = a decision taken with no bit woken: the build on its sections. Deaths' killer from cold `BotLifeState` (the round's death event) and hot `Die`; `scripts/trace.js --bot <id>` a bot's timeline, without `--bot` the situation → decision summary. Thresholds: searches ≤ 7/bot-h, builds ≤ 8/bot-h, workshop ≤ 4 per crafter-hour, board wakes ≤ 2/bot-h, rebuff trips ≤ 1/bot-h, forming judged ≤ 10× formed.
- Decision registry (`planning/target-architecture/decision-registry.js` + `.json`): every duration constant, clock comparison, timer and per-step/per-tick call in Bot, Clan, ClanHall, AfkTrade, Social, RaidBoss classed; exit 0 required (1 = an unclassified site), `--stale` lists keys of deleted windows; dynamic calls show as `decided:<decision>:unwoken:<caller>`.

## Worker boundary

- **May run:** pure modules that get lookups as arguments, stubbed modules (`Database` proxy that rejects every call,
  EffectStore, ChargeLifecycle, BotRaidSafety, MarketOpportunity, NpcShopBuyLists, SummonControl, WorldAreaCatalog,
  TownRespawn, GameTime, WorldConstants), table mirrors.
- **May not:** `Database`, `GameServer/World/*`, `BotManager`, `Network`, `Server`, anything reaching the DB,
  `SpotService.findById`/`ensureIndexed`.
- **Guard gaps:** the guard only wraps `invoke()`; relative `require()` passes (used on purpose for
  `CharacterLocationRuntime`, `CharacterStateSources`); the `require.cache` scan runs once, so a lazy invoke throws only
  when reached. ~67 `isMainThread` uses (103 occurrences) in 36 files choose behaviour per thread (EconomyContext 19, ClanSupplyPolicy,
  TableMirror, BotLifeState, PersonalWarehouseIndex, BotPersona, ColdEconomyDecision, ShotCraftPolicy, …).
